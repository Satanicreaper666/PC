level: Senior

stage: recruit
checked: 2026-11-02
summary: "This role keeps a high-volume platform reliable, fast and easy to deploy. Success means agreed service levels met, incidents resolved quickly and learned from, and less manual work for engineering teams."
responsibilities:
  - "Design and maintain CI/CD pipelines using tools such as GitHub Actions, Argo CD and Kubernetes"
  - "Define service level objectives and indicators, and track error budgets for production services"
  - "Lead incident response: the on-call rota, runbooks, blameless post-mortems and lasting fixes"
  - "Automate infrastructure on AWS or GCP using Terraform and Ansible"
  - "Monitor system health with Prometheus, Grafana and alerting, and work to cut the time to recover"
  - "Apply security basics: secrets management, least-privilege access and vulnerability scanning"
  - "Support engineering teams on release readiness, capacity planning and cloud costs"
competencies:
  - { name: "Kubernetes and containers", type: Technical, level: "Expert" }
  - { name: "CI/CD pipeline design", type: Technical, level: "Expert" }
  - { name: "Infrastructure as code (Terraform)", type: Technical, level: "Expert" }
  - { name: "Observability", type: Technical, level: "Proficient" }
  - { name: "Cloud platforms (AWS, GCP or Azure)", type: Technical, level: "Expert" }
  - { name: "Incident management", type: Behavioural, level: "Proficient" }
  - { name: "Python or Bash scripting", type: Technical, level: "Proficient" }
mustHave:
  - "Has worked in DevOps, SRE or platform engineering"
  - "Has run Kubernetes in production, not only in local or test clusters"
  - "Has managed infrastructure across several environments on AWS or GCP with Terraform"
  - "Has been on call and led post-mortems that produced lasting fixes"
goodToHave:
  - "Certified Kubernetes Administrator (CKA)"
  - "Experience with a service mesh such as Istio or Linkerd"
  - "Has cut cloud spending by a measurable amount"
interview:
  - q: "Walk me through the most complex incident you handled. How were you thinking during the outage?"
    look: "Stabilises first, communicates clearly, forms and tests hypotheses, and follows up with a blameless review and fixes to the system rather than blame."
  - q: "How do you decide when manual work should be automated and when to accept it?"
    look: "Weighs how often it happens, the risk and the time saved against the cost of building and maintaining automation, with an example of each choice."
  - q: "Describe a time you pushed back on a development team to keep deployment standards."
    look: "Explains the risk in terms the team cares about, offers a path that keeps them moving and gets agreement rather than simply blocking."
greenFlags:
  - "Has cut recovery time or increased deployment frequency, with data to show it"
  - "Keeps runbooks and documentation current as part of the job"
  - "Can explain why Kubernetes was, or wasn't, the right choice at a given scale"
redFlags:
  - "Can't explain service level objectives or error budgets"
  - "Has used only managed container services, for a role that runs Kubernetes directly"
  - "Accepts 'it works on my machine' as good enough"
